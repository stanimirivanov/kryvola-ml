# kryvola-ml essentials

- Start with README and [architecture/enforcement](docs/architecture.md); use linked design/plan sections when relevant. [Progress](docs/progress.md) distinguishes scaffold from remaining roadmap work.
- Setup: `uv sync --locked`. Fast: `uv run --locked python tools/verify.py fast`. Full: `uv run --locked python tools/verify.py full`. Inspect: `uv run --locked python -m kryvola_ml`.
- The owner domain retains private keys. SDK/planner code consumes released spec contracts and packaged owner bindings, never fabric/engine internal source. The planner must reject unsupported trust/precision/evidence requirements; no planner or model is yet implemented.
- Author non-OpenAPI contracts in the spec repository with Effect v4 / TypeScript 7; OpenAPI uses Redocly. Consume generated release artifacts; do not import sibling implementation source or hand-edit vendored contracts.
- Preserve exact toolchain/lock versions. Updating `spec.lock.json` requires the matching immutable source revision, generated bytes and full provenance verification.
- No private key, ciphertext/proof blob, credential or plaintext witness belongs in control-plane messages or logs. Structural metadata validation is not authorization or proof of cryptographic security.
- Complete when affected checks pass, custom negative controls remain effective, progress matches observed evidence, and only issue-related changes are staged.
- Follow the authorized dedicated-issue/branch/PR workflow. Preserve unrelated work; do not merge, poll CI or revise a delivered PR without an explicit request.
- Before committing, run automatic formatting and lint fixes on supported authored files, then recheck affected gates. Preserve vendored `_spec`/`_wire` bytes exactly; keep heavy checks on CI when requested.
